# Alterlit · Иллюстрации

Остров на React для страницы [alterlit.ru/images/illustrators/](https://alterlit.ru/images/illustrators/):
лента иллюстраций с бесконечной подгрузкой, просмотр картинки в диалоге, лайки и комментарии
с живыми обновлениями. Встраивается в Django-шаблон сайта и работает с его API по сессионной куке.

## Что умеет

- **Лента** сеткой в 3 колонки (2 на узких экранах) с бесконечной подгрузкой и скелетонами.
  Пока грузится оригинал, показывается размытое превью — оригинал «проявляется» поверх.
- **Лайки** с мгновенным откликом и короткой анимацией; гостю — окно с объяснением.
- **Диалог просмотра**: картинка, автор со ссылкой на профиль, лайки, «Скачать»,
  просмотр во весь экран (Fullscreen API, на iPhone — слой на всё окно).
- **Комментарии**: список с ответами второго уровня, подгрузка более ранних, санитизация HTML.
- **Вид комментариев и формы** повторяет комментарии на страницах текстов сайта
  (`/assets/comments/`): та же разметка, иконки, даты, свёрнутые ответы.
- **Форма комментария** (Tiptap): форматирование всплывает над выделенным текстом (жирный,
  курсив, подчёркнутый, ссылка), упоминания `@` с автодополнением, до 3 картинок (кнопкой,
  вставкой, перетаскиванием), Ctrl+Enter.
- **Жалобы** на чужие комментарии — и от вошедших, и от гостей (гость указывает email).
- **Живые обновления** через WebSocket: новые, изменённые и удалённые комментарии.
- **Отправка** с мгновенным показом: комментарий появляется сразу и подтверждается сокетом
  или ответом сервера; при ошибке текст и картинки возвращаются в форму.
- **Правка и удаление**: `is_staff` — любые комментарии в любое время; остальные — свои
  в течение 5 минут после отправки, с таймером.

## Стек

React 19, TypeScript, Redux Toolkit (RTK Query, в том числе infinite queries), Vite 8 (Rolldown),
Tiptap 3, DOMPurify. Без UI-библиотек — стили свои, токены сняты с alterlit.ru.

## Быстрый старт

Нужен Node.js 22+.

```bash
npm install
cp .env.example .env.local   # и заполнить куки, см. ниже
npm run dev                  # http://localhost:5181/images/illustrators/
```

### Куки для разработки

API сайта работает по сессионной куке. Чтобы не логиниться через localhost, dev-прокси Vite
подставляет куки в запросы к `/api` и в сокет `/ws`. Возьмите их в DevTools на alterlit.ru
(Application → Cookies) и впишите в `.env.local`:

```dotenv
DEV_SESSION_ID=<alterlitsessionid>
DEV_CSRF_TOKEN=<csrftoken>
```

`.env.local` в репозиторий не попадает. Переменные намеренно без префикса `VITE_` —
так они остаются в Node и не могут оказаться в клиентском бандле.

> ⚠️ Это рабочая сессия. Dev-сервер слушает все интерфейсы (`host: true`), и любой, кто до него
> дотянется, действует от имени этой сессии. Не держите его открытым наружу дольше нужного;
> для локальной работы запускайте `npx vite --host 127.0.0.1`.

### Что ещё делает dev-сервер

- `/` перенаправляет на `/images/illustrators/`.
- `index.html` грубо повторяет страницу сайта (шапка, колонка `main`, сайдбар), чтобы видеть
  остров в его окружении. В сборку не попадает.
- Проксирует на alterlit.ru `/api` (с куками и правильными `Origin`/`Referer` для CSRF),
  `/ws` (сокет), `/media`, `/assets` (шрифт Ethna, текстура) и `/profile`.
- `?slug=` в адресе переопределяет ленту: пустой `?slug=` — общая лента всех картинок.

## Сборка и выкладка

Статика на проде отдаётся с `/assets/images_list/`. После `npm run build` в `dist/` пять файлов
с постоянными именами:

| Файл | Как попадает на страницу |
|---|---|
| `images_list.css` | шаблон |
| `images_list.js` | шаблон, точка входа |
| `vendor.js` | React, Redux — грузит `images_list.js` |
| `rolldown-runtime.js` | служебный код сборщика — грузит `images_list.js` |
| `editor.js` | редактор комментариев — только вошедшим и по требованию |

Подключение в Django-шаблоне (полный пример — `django_template_example.html`):

```html
<link rel="stylesheet" href="/assets/images_list/images_list.css?v={{ IMAGES_LIST_VERSION }}">
<div id="alterlit-illustrators"></div>
<script type="module" src="/assets/images_list/images_list.js?v={{ IMAGES_LIST_VERSION }}"></script>
```

- `type="module"` обязателен: остальные бандлы приложение подгружает само через `import`.
- При каждой выкладке меняйте `IMAGES_LIST_VERSION` — это сбрасывает кэш точки входа.
  Импорты между бандлами сборка сама помечает `?v=<хэш сборки>`, так что и `vendor.js`
  с `editor.js` после выкладки берутся свежими, хотя имена файлов не меняются.
- Другой префикс статики: `STATIC_BASE=/s/images_list/ npm run build`.
- Slug ленты — последний сегмент адреса страницы: `/images/illustrators/` → `illustrators`.

На стороне сервера: nginx должен пропускать апгрейд до WebSocket на `/ws/` и принимать тела
запросов до ~32 МБ (`client_max_body_size`) — три картинки по 10 МБ в одном комментарии.

## Устройство

```
src/
  api/                 RTK Query: лента, сессия, лайки, комментарии (baseApi — общая база)
  app/                 store и типизированные хуки
  features/
    feed/              лента, карточка, общие кусочки (картинка с «проявлением», лайк, аватар)
    viewer/            диалог просмотра, полноэкранный просмотр, окно-предупреждение
    likes/             обработчик лайка
    discussion/        список комментариев, сокет, кэш, отправка/правка/удаление, окно правки
    comments/          форма и редактор Tiptap, упоминания — отдельный бандл editor.js
  lib/                 slug страницы, CSRF
  styles/index.css     все стили острова, под .illustrators и с префиксом il-
docs/backend-api.md    справка по API и моделям бэкенда
```

Несколько решений, о которых стоит знать:

- **Бандлы.** Код в `src/features/comments/` и Tiptap уходят в `editor.js`, библиотеки — в
  `vendor.js`. `editor.js` не должен импортировать код ленты: точку входа шаблон грузит со
  своим `?v=`, и импорт без того же `?v=` запустил бы приложение второй раз. Плагин
  `versionChunkImports` в `vite.config.ts` следит за этим и падает со сборкой, если такое случится.
- **Мгновенная отправка.** Комментарий сначала кладётся в кэш как «отправляемый» с отрицательным
  id, затем подтверждается тем, что придёт раньше: событием `new_comment` из сокета или ответом
  POST. Повторные события с известным id игнорируются (`features/discussion/commentsCache.ts`).
- **Время.** Бэк отдаёт даты в московском времени без пояса; окно правки в 5 минут считается от
  `dt` как от UTC+3 (`features/discussion/editWindow.ts`).
- **Стили сайта.** Legacy CSS alterlit.ru стилизует голые теги (`header`, `footer`, `h1`, `h2`,
  `main p`, `ul li`…), поэтому в острове нет `header`/`footer`, а пересекающиеся правила
  сброшены внутри `.illustrators`.
- **Безопасность.** Комментарии — пользовательский HTML и выводятся только через DOMPurify с
  белым списком тегов; из iframe пропускаются лишь встраивания YouTube.

## API бэкенда

Ручки, формат ответов, события сокета, модели `Comment` и `PostImages` и найденные странности
описаны в [`docs/backend-api.md`](docs/backend-api.md). Коротко:

| Ручка | Назначение |
|---|---|
| `GET /api/v1/users/session/self/` | текущий пользователь (гость — 403) |
| `GET /api/v1/images/session/?slug=&last_id=` | лента картинок |
| `POST /api/v1/like/session/postimages/<id>/` | переключить лайк |
| `GET /api/v1/session/autocomplete/users/?q=` | автодополнение упоминаний |
| `GET /api/v1/comments/postimages/<id>/session/` | комментарии картинки |
| `POST` там же | новый комментарий (multipart) |
| `PATCH`/`DELETE /api/v1/comment/<id>/session/` | правка (multipart) / удаление |
| `POST /api/v1/support/task/session/` | жалоба на комментарий (multipart) |
| `wss://…/ws/comments/postimages/<id>/` | события `new_comment`, `change_comment`, `remove_comment` |

### Известные проблемы на бэке

- Автодополнение падает с 500 на любом `limit`/`offset` (строка сравнивается с числом) —
  вторая страница подсказок пока не грузится.
- Лайк на несуществующий id отвечает 200 вместо 404.
- Сокет закрывает соединение (1011) на любое сообщение от клиента — клиент ничего не отправляет.
- Ручка жалоб не проверяет поля (пустой текст и неверный email проходят), а гость без email
  получает 500 вместо понятной ошибки.
